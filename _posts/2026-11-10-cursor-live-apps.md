AI 코딩 에이전트로 자리 배치표나 영업 대시보드 같은 작은 도구를 만들어도 대부분은 내 노트북의 localhost에서 끝난다. 동료에게 보여 주려면 서버, 데이터베이스, 로그인을 따로 붙여야 해서다. Cursor가 11월 5일 낸 'Apps'는 이 마지막 단계를 에이전트에게 맡긴다. 이 글을 읽으면 Cursor로 만든 사내 앱을 어디서 시작해 누구에게까지 공유할지 정하고, 배포 전에 무엇이 막히는지 미리 알 수 있다.

{: .summary }
> - **클라우드 에이전트**에게 "앱을 만들어 달라"고 분명히 말하면 웹앱·Postgres DB·로그인·호스팅까지 붙여 **링크 하나**로 내준다. 로컬 에이전트에서는 안 된다.
> - 공개 범위는 **초대한 사람 / 팀 / 공개** 셋이다. 팀·엔터프라이즈는 **공개가 기본으로 꺼져** 있다.
> - 배포 전에 **항상 켜진 검사 4개**와 AI 보안 검토가 돈다. 개인 요금제는 클라우드 에이전트가 들어가는 **Premium(월 30달러)**부터다.

## 무엇이 바뀌었나: localhost에서 끝나던 앱이 링크가 된다

Cursor 체인지로그에 따르면, 클라우드 에이전트에게 앱을 만들겠다고 하면 Cursor가 웹앱 뼈대를 세우고, 필요하면 Postgres 데이터베이스를 띄우고, Cursor SSO 뒤에 로그인을 걸고, 호스팅까지 잡는다. 데이터 웨어하우스처럼 회사 시스템에 붙어야 하면 필요한 비밀 값(시크릿)을 물어본다. 게시할 때 고유한 주소를 고르면 실제로 열리는 링크가 나온다.

문서는 각 부분을 이렇게 설명한다.

| 부분 | Cursor가 하는 일 |
|---|---|
| 호스팅 | 팀(개인 요금제는 본인)마다 따로 만든 계정에 배포, 다른 팀·사용자와 격리 |
| 데이터베이스 | 필요하면 Postgres를 자동으로 만든다 |
| 로그인 | 비공개·팀 앱은 Cursor 로그인 뒤에 둔다 |
| 시크릿 | 값을 입력받아 쓰고, 에이전트는 값을 보지 못한다 |

Cursor는 사내에서 영업·운영·법무·재무·엔지니어링 직원이 행사 등록, 계정 배정, 자리 배치 같은 운영 도구와 신입 온보딩 자료, 영업 파이프라인 대시보드를 이렇게 만들어 쓴다고 소개했다.

## 만드는 순서: 클라우드에서 시작하고, 게시는 내가 누른다

문서가 밝힌 시작 방법은 단순하다. 다만 클라우드 에이전트여야 하고, 로컬에서는 이 기능이 지원되지 않는다.

1. 클라우드 에이전트를 연다. 데스크톱 앱에서는 에이전트 입력창 아래 드롭다운에서 Cloud를 고르고, 웹에서는 cursor.com/agents에서 시작한다
2. 앱을 만들겠다고 분명히 쓴다. 새로 만들면 Cursor Origin에 새 저장소가 생기고, 기존 GitHub 저장소라면 "Deploy this repo as an app."처럼 배포를 시킨다
3. 앱이 준비되면 나오는 트레이에서 미리 보고, 게시할 때 앱 주소를 고른다(나중에 바꿀 수 있다)
4. 보안 검사가 통과하면 링크가 나온다. 막히면 에이전트가 고칠 목록을 보여 주니, 고치라고 시킨 뒤 다시 게시한다
{: .steps }

문서 예시 프롬프트는 "주간 가입자를 차트와 요금제별 필터가 있는 표로 보여 주는 대시보드 앱", "팀이 버그를 제보하고 상태를 추적하는 사내 앱" 같은 식이다. 무엇을 보여 주고 누가 무엇을 입력하는지를 한 문장에 담는다. 체인지로그는 GitLab 같은 다른 Git 제공자 지원은 곧 나온다고 했다.

## 누구에게 보여 줄지 고르는 법

공개 범위는 세 가지다. 초대한 사람(People you invite)은 Cursor에 로그인한 특정 팀원·그룹만, 팀(Team)은 Cursor 팀 전체, 공개(Public)는 링크를 가진 누구나 연다. 팀·엔터프라이즈에서는 공개가 기본으로 꺼져 있고 팀 관리자가 Apps 대시보드에서 켜야 한다.

~~~mermaid
flowchart TD
  A[누구에게 보여 주나] --> B{회사 밖 사람도?}
  B -- 예 --> C{개인 요금제?}
  C -- 예 --> D[Public]
  C -- 아니오 --> E[관리자 허용 필요]
  B -- 아니오 --> F{팀 전체?}
  F -- 예 --> G[Team]
  F -- 아니오 --> H[초대한 사람만]
~~~

사람이 아니라 스크립트나 CI 작업이 앱을 불러야 할 때도 있다. 비공개·팀 앱은 Cursor 로그인 뒤에 있어 자동화 도구가 그냥 들어오지 못한다. 이때는 Cursor API 키를 `x-cursor-app-token` 헤더에 실어 보낸다. 쿼리 문자열이나 쿠키로는 안 되고, 요청마다 헤더를 붙여야 한다. 개인 키는 주인이 열 수 있는 앱을, 팀 키는 권한을 받은 팀 앱만 연다.

~~~bash
curl -H "x-cursor-app-token: $CURSOR_API_KEY" https://<앱 주소>
~~~

## 배포 전에 막아 주는 것과 남는 책임

게시할 때마다 도는 검사 4개는 보안 검토를 꺼도 항상 켜져 있다.

- **앱 파일 속 비밀 값 차단**: 파일에 API 키나 액세스 토큰이 있으면 게시를 멈춘다
- **자격 증명 파일 차단**: 개인 키, 서비스 계정 키, 인증 토큰이 든 파일이 있으면 멈춘다
- **.env 제외**: `.env` 파일은 배포본에서 뺀다
- **소스맵 제외**: 방문자가 원래 소스 코드를 읽지 못하게 소스맵을 지운다

여기에 AI 보안 검토가 앱 파일을 읽고 심각한 문제를 막는다. 팀 관리자는 검토 프롬프트에 자기 규칙을 더할 수 있지만 기본 검사를 뺄 수는 없다.

관리자는 팀 전체의 앱과 시크릿을 보고, 어떤 앱이든 게시를 내리고, 검토가 막은 게시를 승인할 수 있다. 다만 악성 코드, 하드코딩된 비밀 값, 노출된 자격 증명으로 막힌 것은 승인할 수 없다. 설정을 바꾸면 팀 감사 로그에 남는다.

{: .warning }
Cursor 문서는 앱과 그 결과물에 대해 책임지지 않고, 호스팅은 서비스와 별개로 "있는 그대로" 제공되며, 약관 위반이나 사업·재무·법적 이유로 서브도메인과 앱이 내려질 수 있다고 적었다. 고객 데이터나 업무에 꼭 필요한 시스템을 올리기 전에는 회사 보안 담당과 먼저 정하는 편이 안전하다.

## 누가 쓸 수 있고 얼마인가

Apps는 클라우드 에이전트를 쓸 수 있는 모든 유료 요금제에서 열린다. Cursor 요금 페이지 기준으로 개인 요금제 중 클라우드 에이전트가 들어가는 것은 Premium부터다.

| 요금제 | 월 요금 | 클라우드 에이전트 |
|---|---|---|
| Free / Plus | $0 / $8 | 없음 |
| Premium / Super / Ultra | $30 / $100 / $200 | 있음 |
| Teams | 사용자당 $30부터 | 있음 |

요금 페이지는 제3자 모델 사용료가 월 요금에 들어 있지 않고 사용량만큼 따로 청구된다고 적었다. 앱 호스팅이나 데이터베이스에 따로 돈이 드는지는 문서와 요금 페이지에 나와 있지 않다.

{: .interpret }
이 기능이 바꾸는 것은 코드를 쓰는 속도보다 "누가 사내 도구를 배포할 수 있나"다. 지금까지는 개발팀이 서버·인증·DB를 맡아 줘야 했다면, 이제 영업이나 재무 담당도 링크까지 직접 만든다. 그만큼 관리자가 정할 일이 늘어난다. 공개 허용, API 키 허용, 검토 규칙을 처음부터 정해 두지 않으면 누가 무엇을 올렸는지 나중에 대시보드에서 거꾸로 찾게 될 수 있다.

## 마무리

Apps를 써 보기 전에 먼저 정할 것은 프롬프트가 아니라 공개 범위와 시크릿 관리다. 팀이라면 관리자가 Apps 대시보드에서 공개 앱·API 키·검토 규칙을 먼저 정해 두고, 첫 앱은 회사 데이터를 쓰지 않는 자리 배치표 같은 작은 도구로 시작하면 위험을 줄이면서 흐름을 익힐 수 있다.
